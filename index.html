00 What is MnExMnEx 是什么

MnEx is a platform for building, deploying, and monetizing AI agents. It originated from the OpenClaw personal multi-agent system and is evolving into an open platform where third-party developers supply the agent marketplace.

MnEx 是一个用于构建、部署和商业化 AI Agent 的平台。它源自 OpenClaw 个人多 Agent 系统， 正在演进为一个开放的 Agent 平台，Agent 市场由第三方开发者供给。

For Developers

面向开发者

Publish agent and team definitions to the marketplace. Define capabilities, composition rules, and pricing. Receive revenue share when users install your agents.

在市场中发布 Agent 和 Team 定义。设定能力、编排规则与定价。 用户安装你的 Agent 后即可获得收益分成。

For Individuals & Organizations

面向个人与组织

Browse and install agents into your Groups. Agents learn and adapt within your context. Manage permissions at the instance level.

浏览市场并将 Agent 安装到你的 Group 中。 Agent 在你的上下文中学习与适应。在实例级别管理权限。

App Store Model

App Store 模式

Developers ship definitions; users install instances. This separation enables safe multi-tenancy — each Group runs its own instances with isolated memory.

开发者发布定义，用户安装实例。这种分离实现了安全的多租户架构—— 每个 Group 运行自己的实例，记忆完全隔离。

01 Four-Layer Primitive Architecture四层原语架构

The platform is built on four orthogonal layers, each solving one problem. Layers depend top-down: Entity → Relation → Asset → Permission.

平台建立在四层正交原语之上，每层只解决一个问题。 从上往下依赖：Entity（实体）→ Relation（关系）→ Asset（资产）→ Permission（权限）。

MnEx Four-Layer Primitives 1. Entity ✅ Independent things in the system ├── Agent ad_ / a_ Definition · Instance · Context (3-layer identity stack) ├── Person p_ Self-registration, default Group ├── Team td_ / t_ Definition · Instance, install flow └── Group g_ Default + user-created, role-based permissions 2. Relation ✅ How entities connect and transition ├── Person ∈ Group N:N, invite / leave / kick / transfer ├── Team ↔ Group Bind / unbind, N:1 Team→Group ├── Agent ∈ Team N:1, installed alongside Team └── Agent ↔ Person Derived from chain, no direct link 3. Asset ✅ Things entities produce or own ├── Interaction memory Instance + Person level ├── Output memory Instance level └── Agent knowledge Definition level 4. Permission ✅ Data access authorization ├── Default open Owner has natural access ├── Revoke → tighten Explicit deny overrides └── Dual check chain Asset access label → Permission revoke
MnEx 四层原语架构 1. Entity（实体） ✅ 系统中独立存在的东西 ├── Agent ad_ / a_ 定义层 · 实例层 · 上下文层（三层身份栈） ├── Person p_ 自注册即激活，默认 Group ├── Team td_ / t_ 定义层 · 实例层，安装流程 └── Group g_ 默认 Group + 用户创建，角色权限 2. Relation（关系） ✅ 实体之间如何关联与变迁 ├── Person ∈ Group N:N，邀请 / 退出 / 踢人 / 转让 ├── Team ↔ Group 绑定 / 解绑，Team→Group 多对一 ├── Agent ∈ Team N:1，随 Team 安装诞生 └── Agent ↔ Person 从链路推导，不独立存在 3. Asset（资产） ✅ 实体产生或拥有的东西 ├── 交互记忆 实例 + Person 级 ├── 产出记忆 实例级 └── Agent 自身知识 定义级 4. Permission（权限） ✅ 数据访问授权 ├── 默认全开 所有者天然拥有 ├── Revoke 收紧 显式拒绝覆盖 └── 双重检查链 Asset access 标签 → Permission revoke

Core chain: 核心链路： Person p_xxx ∈ Group g_xxx → bind Team t_xxx → contains Agent a_001, a_002

06–10 Entity Specifications实体设计规范

Four entity types with a unified six-prefix ID system, each 12 hex digits.

四类实体，统一六前缀 ID 体系，均为 12 位十六进制。

Agent

ad_ / a_

Three-layer identity stack: definition (published by developer), instance (created when Team is installed), and context (runtime, discarded after session).

三层身份栈：定义层（开发者发布）、实例层（Team 安装时创建）、 上下文层（运行时栈帧，session 结束即丢弃）。

Person

p_

The atomic entity. Self-registration activates a Person. Each Person automatically gets a default Group (single-person). Contact fields for reachability.

原子实体。自注册即激活。每个 Person 自动获得默认 Group（单人）。 包含联系方式字段。

Team

td_ / t_

A collection of Agents. Definition published by developer; instance created when a Group installs the Team. Team composition defines collaboration rules.

Agent 的集合。开发者发布定义，Group 安装时创建实例。 Team composition 定义协作规则。

Group

g_

A collection of Persons. Default single-person Group created automatically; user-created Groups for teams. Role-based permissions and member management.

Person 的集合。默认单人 Group 自动创建；用户可创建多人群组。 角色权限与成员管理。

Foundational choices that shape the entire platform.

塑造整个平台基调的基础决策。

Decision决策项 Outcome结论
User model用户模型 Individual = single-person Group; unified data model个人 = 单人 Group，统一数据模型
Market model市场模型 App Store analogy — developers publish definitions, users install instancesApp Store 类比——开发者发定义，用户装实例
Entity model实体模型 Agent / Person / Team / Group — four typesAgent / Person / Team / Group 四类
ID systemID 体系 Six prefixes (ad_/a_/td_/t_/p_/g_), 12 hex digits六前缀（ad_/a_/td_/t_/p_/g_），12 位十六进制
Architecture架构原则 Four-layer primitives, top-down dependency四层原语，从上往下依赖
Entity isolation实体隔离 Group → Team → Agent, no cross-layer accessGroup → Team → Agent，不跨层
Memory isolation记忆隔离 Four-link chain; cross-Group learning only via definition upgrades四层记忆链路；跨 Group 学习仅走定义升级
Preference control偏好控制 Field-level access tags, self-describing字段级 access 标签，自描述
